# Restic 加密备份与应用内恢复方案

## 目标

- `/vol2/1000/honvin` 作为一个 Restic 任务备份到 pCloud。
- pCloud 只保存 Restic 加密仓库；文件名、目录名和内容不会明文暴露。
- pCloud NAS Sync 内可以查看快照、按原目录浏览、下载单个文件、把文件夹打包为 ZIP 下载，以及恢复到 NAS 的专用恢复目录。
- 旧 `.pcenc` 解密浏览能力已按用户决定移除；原 `/mybackup/jiamisync` 已确认全为 `.pcenc` 后删除。
- 原有压缩包必须先解压并核验；正式备份只上传解压后的目录树，不重复上传旧压缩包。

## 数据路径

- 本地源：只读挂载 `/vol1`、`/vol2`。
- pCloud 仓库：任务的 `remotePath`，推荐 `/restic-backups/honvin`。
- Restic 传输：容器内仅监听 `127.0.0.1` 的 REST 适配器。每个 Restic 对象先暂存为本地临时文件，再以明确的 Content-Length 上传 pCloud，避免 pCloud 对未知长度流式上传卡死。
- 密码：每个任务独立保存在 `/data/restic/secrets/<task-id>.password`，权限 `0600`；不进入配置 API 和日志。
- 恢复：只写入 `/restore`（宿主机默认 `/vol1/1000/pcloudbackups/restic-restore`），不允许覆盖原始备份源。

## 正式备份排除项

- `温湿度` 数据以及回收站、系统缓存和临时文件。
- `rar`、`zip`、`7z`、`tar`、`tgz`、`gz`、`bz2`、`xz` 及常见分卷压缩文件；这些压缩包必须先解压，Restic 只备份解压结果。

## 快照目录索引

- 本地 SQLite 保存已经完成的快照目录索引，浏览快照和进入目录不再逐次访问 pCloud。
- 每次备份成功并执行保留策略后，应用读取新快照目录，流式写入本地暂存索引；完整结束后才原子标记为可用。
- 完整目录索引使用 gzip 压缩，并使用从 Restic 密码和随机 salt 派生的 AES-256-GCM 密钥加密后上传到 pCloud。
- 小型 `catalog.json` 只包含任务 ID、仓库路径、快照 ID、索引文件、哈希和时间，不包含原文件名；它使用从 Restic 密码派生的 HMAC-SHA256 签名。
- 索引文件先上传，`catalog.json` 最后上传。App 启动先显示本地缓存，再后台下载 catalog；快照 ID 不同才下载、校验、解密和导入新索引。
- 云端索引缺失、损坏或签名错误时保留旧缓存，并回退到 Restic 原始仓库；它不会修改 NAS 原文件或 Restic 备份数据。

## 操作模型

1. 首次备份自动初始化 format v2 仓库，启用自动压缩。
2. 后续备份由 Restic 按内容分块去重，只上传新增或变化的数据块。
3. 默认保留最近 7 个日快照、4 个周快照、12 个月快照；备份后执行 `forget`，不自动 `prune`，避免频繁重写 pCloud pack。
4. `check`、`prune` 为明确的独立操作。`prune` 在界面中必须二次确认。
5. 浏览调用非递归 `restic ls --json`；下载/恢复使用 `restic restore` 到隔离临时目录。
6. 文件夹 ZIP 完成后再提供下载，下载完成后清理临时目录。

## 安全边界

- 所有 Restic/rclone 命令使用参数数组启动，不经过 shell。
- 浏览路径必须位于任务的 `localPath` 下；远端路径拒绝 `.`、`..`。
- 备份源挂载只读；恢复仅能落到 `/restore`。
- 密码只能显式设置或显式导出恢复信息，状态接口只返回“已配置/未配置”。
- 应用不自动删除旧 pCloud 目录，也不自动启动 honvin 全量上传。

## 迁移验收

1. 用小测试目录创建仓库并完成两轮备份。
2. 确认第二轮只上传变化的数据，`restic check` 通过。
3. 应用内能看到快照和明文目录树。
4. 单文件下载内容和哈希一致；文件夹 ZIP 可解压且目录结构一致。
5. 恢复到 `/restore` 后与测试源核对。
6. 所有压缩包解压及核验完成后，再由用户确认创建并启动 `honvin` 正式任务。
